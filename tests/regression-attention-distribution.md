# 3.2 阅读、传播与商业承接回归

## 范围与复跑方式

本轮于 2026 年 9 月 15 日进行三次独立前向试用，共覆盖七个场景。执行者只收到当前 Skill、按需 references 和指定原始输入，没有得到设计答案、预期结果、Git 差异、升级审计或旧测试结论；各自产物在仓库外生成，再由主执行者逐项对照输入与规则核验。归档只规范化机器路径和末尾空白，实际答复未改写。

输入为 [attention-scenarios.md](fixtures/attention-scenarios.md) 的 P、N、X、B0、B1、S 六个合成场景，以及 [既有可逆选择完整成稿](fixtures/reversible-choice-article.md)。合成输入明确不代表 Tang 的现实经历或业务，不据此发布、联系客户或证明学术事实。复跑时把对应输入交给未读过本回归记录的执行者，要求实际交付，再按下面的行为标准核验；不要用命中关键词或抄出规则代替行为判断。

测试覆盖三组历史设计样本所暴露的风险，但不是本轮逐篇重新测试《权力》八篇或虚构故事全文。既有可逆选择成稿本轮实际完整读取；其他旧回归只进行文件保全与依赖规则检查，不改写其历史通过、部分通过或缺口记录。

## 行为结果

| 场景 | 需要观察的行为 | 本轮实际结果 | 结论范围 |
| --- | --- | --- | --- |
| P 强观点 | 收窄样本外推，保留可用判断，不用身份贬损代替解释；标题与截图也不过界 | 没有沿用“研究证明”与“听话永远没权力”，明确公司自述及缺少对照；交付成果展示与评审反馈的正文、标题和独立转发句 | 事实及表达边界通过，传播效果未验证 |
| N 不完整现场 | 及时给出改变责任理解的事实，不补心理与现场，仍能保留阅读问题 | 第一段即交代已有暂停回复；第二段将未知放在内部为何仍写“失联”，不推定隐瞒或推责 | 两段叙事改写通过 |
| X 虚构迁移 | 技术可迁移，私人情节不能当真实人物证据，结构不虚构材料 | 给出物件、称谓、回环的条件式用法及结构；明确称谓变化不自动证明关系变化，未知事实等待材料 | 方法与结构方案通过，无真实故事成稿 |
| 可逆选择 | 保留最小模型、反例、退出成本和承诺条件，改善入口而不改成强情节 | 保留章节和四问，只建议标题、两段入口与两个传播单元；必要条件随单元保留，没有新增产品入口 | 原稿保护及传播包装通过，无新一轮外部事实核验 |
| B0 供给未知 | 收入紧迫改变资源排序，同时不编造读者、服务、业绩或入口 | 选择已有笔记可支撑的项目决策方法文，读者与标题标为假设；明确两天生产上限、反馈问题及验证窗口，没有虚构交易 | 选题与需求验证设计通过，无产品或成交验证 |
| B1 供给已知 | 正文先独立有用，再用真实供给和渠道明确承接；区分询问与收入 | 提纲、完整开头和结尾均已交付；明确复盘范围、报价需确认、后台留言入口、适配条件及无成功保证，并记录有效询问到实收和履约成本 | 转化稿件片段与验证设计通过，未完成整篇正文或实际运营 |
| S 协作归属 | 传播目标不破坏目录清洗、作者角色与来源边界 | 不把三百目录项称为三百原创文章，不把转述稿句式归于主讲者；提出账本与原稿对照，没有把重复出现当传播效果证据 | 研究口径与首步方案通过，未读取实际语料全集 |

## 可检查的实际产物

[强观点、叙事与虚构迁移完整答复](outputs/rhetoric-forward.md) 中，P 的转发句是“成果值得被看见，没晋升也不等于你不敢争取”。它在失去正文上下文后没有变成“展示即可晋升”的因果保证；正文也保留了主动整理成果、了解评审标准和索取具体反馈的可用动作。其锋利度没有用绝对化补回，但单次编辑评估不能证明吸引力或转发率提高。

N 把已知预算冻结放在首段，让问题转向“为什么内部仍使用失联说法”，而不是把关键回复留到结尾。材料没有说明内部邮件作者是否读到回复，答复明确保留未知；没有添加会议室、语气、眼神、对白或此后结果。X 只给出可用事实到来后的技术方案，没有替真实人物写出私人故事。

[认知保护与协作归属完整答复](outputs/cognitive-forward.md) 中，首选标题指向下一笔项目投入，后文阅读动力来自信息、试验、停止权和承诺条件。原稿中的最低充分承诺、他人承担的退出成本与选项维持成本继续保留。两个传播单元脱离原稿后仍带试验真实性、退出成本或稳定投入的条件，没有把可逆试验简化为“永远留后路”。建议的新开头与接回原文处略有重叠，属于尚待作者选择标题后处理的局部编辑余量，不影响模型保护结论。

[商业两种供给状态完整答复](outputs/business-forward.md) 中，B0 没有因缺业务信息停在问卷，也没有为了收入目标编出咨询产品。B1 则明确说明已有测试供给与留言入口，读者能看清下一步；有效询问、报价、成交、实收和履约成本分开，观察窗口标为本轮建议。两种任务采用不同承接行为，说明新模块不只是重复商业口号。

所有实际答复均以完整段落承载解释，没有半句换行或连续口号式独句段。标题、转发单元标签和必要结构说明独立呈现，不以机械段长阈值判定文风。三位执行者均读取新增传播 reference，按内容需要选择事实、公众号、认知与改稿等其他模块。

## 技术检查与结论强度

官方 Skill 校验通过，既有检查器 23 项自测通过，运行文档本地引用无缺失，界面 YAML 有效，`git diff --check` 通过。12 个保护文件与 3.1 基线换行归一化后完全相同，包含全部旧 tests 与原成稿；原成稿重跑文字检查的汉字、段落和提醒与历史结果一致。

本轮通过的是上述七个场景各自限定的行为检查。没有测试所有文体，没有重新执行原始三组样本的全文压力测试，没有在线 A/B 测试，没有新增收入数据，也没有把模型自测当作真人读者研究。它支持 3.2 进入 PR 审阅和后续真实写作验证，不能承诺爆款、成交或收入提高。
