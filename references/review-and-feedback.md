# 审稿与反馈

## 发布前：先读者，再硬伤

审稿按这个顺序给具体判断：
1. 想不想点：对象、利益、冲突、标题欲望和正文兑现。
2. 读起来爽不爽：开头抓人，中段有故事、信息、解释、反转与判断奖励。
3. 想不想转：可带走的模型、金句、立场及具体转发对象；同时查收藏用途、点赞认同和评论位置。
4. 想不想关注：是否愿意订阅此人未来持续给同种价值。
5. 有没有事实硬伤：承重研究、关键数据、人物事实、核心因果与可能严重误导的判断。

事实是硬门槛，不能用前四项抵消，也不能用事实正确救活前四项皆弱的稿子。不默认打内部总分，不把严谨等同有传播力。

用户问“符合TWS吗”：给最影响读者行动的结论、稿件具体依据和修改方向，区分推测与已有行为。用户随后说“改”：直接按判断完成实质修改，不停在修句建议。

删六种老师味：总结说教、自动中和、假成熟、过度照顾反方、削成正确废话、最后强行升华。必要事实或危险行动边界不是待删的免责声明。

## 一页十问

谁会点，为什么？涉及他的什么利益、情绪、身份？最狠一句是什么？前500字能留住人吗？中途持续有新奖励吗？有没有重新解释现实的模型？最可能截图哪句？转给谁、为什么？为何继续关注？有没有毁掉可信度的事实硬伤？

这是内部检查，不是每篇正文必须出现的十节。短文按篇幅缩放，情感/人物任务不强制塞认知模型。局部任务只做受影响部分。

## 发布测试

具备可以真实测试的稿件后，不为内部99分、100分无限打磨。上传、公开发布、后台操作、外部发送仍需用户针对实际动作授权；没有授权交付准备好的成品。发布后的结果必须来自实际数据，内部检查和模拟读者都不能声称爆款已被验证。

## 数据复盘

优先读者行为链：看到 → 点击 → 继续读 → 觉得值 → 表态 → 传播 → 关注。记录阅读、打开、完读、点赞、转发、推荐、收藏、评论、新增关注，以及后续基础阅读盘。没有数据标未知，不补数字、不用评分代替。

定位瓶颈：
- 没有或不知道曝光：先查送达、曝光和来源，正文尚未获得有效测试。
- 有曝光没人点：优先检验选题、标题、封面。
- 点开后快速退出：优先开头。
- 阅读有量但完读差：检验结构、节奏与信息增量。
- 完读不错没人转：检验判断、模型、金句和表达价值。
- 有转发没关注：检验账号人格、未来内容预期与关注路径。
- 在可比曝光条件下连续整体表现差：选题重新竞争，不继续只润色句子。

上述是调查方向，不是只凭一个数字就证实的原因。给出已知事实、当前假设、缺失数据和下一次具体改动。比较时核对窗口、读者盘、曝光和来源；官方助推、自操作互动、主动分发与自然反馈分开。不把别人的高数据直接当作本账号的效果保证。

真实数据可否决内部好评。连续失效就改系统与选题，不先怪读者或用算法解释保护体系；分发和平台因素可以调查，须有证据。
