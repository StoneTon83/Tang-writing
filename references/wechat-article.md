# 公众号文章

用这份文件处理公众号长文、系列文章和以传播为目标的观点内容。公众号是发布场景，不等于固定文体。先判断文章主要属于经验叙事、认知解释、产业分析还是其他类型，再调用对应模块。

## 入口先建立阅读必要性

开头优先让读者迅速看见一个真实问题。可以来自下面任一种情况。

- 一段读者熟悉的冲突或尴尬。
- 一个动作与结果不匹配的场景。
- 一句能直接接住读者困惑的判断。
- 一个经过核验、足以改变直觉的事实。
- 两个同时像是真的事实发生冲突。
- 一个常见解释无法说明的异常。

不要先解释概念、宣布主题或预告全文结构。理论晚一点进场。

经验、关系和现实摩擦型文章使用场景以后，可以尽快给一句人话翻译，把表层事件翻成代价、关系、权力、责任或选择。认知和研究型文章不强制这一步，只需要尽快说清问题为什么值得继续追。

## 用问题和认知需要推进，不用路标推进

每一部分结束时，最好自然产生下一步需要处理的问题或认知任务。

- 为什么会这样。
- 凭什么相信这个解释。
- 还有什么解释也说得通。
- 这个解释在哪些情况下不成立。
- 哪个条件变化以后，结论会变化。
- 读者怎样判断自己是否也在里面。
- 知道以后应该怎样观察、判断或行动。

下一部分必须兑现前一部分真正留下的问题。不要用“还有一层”“真正的问题”假装深入。

检查大结构时做一次换序测试。若几个章节任意交换几乎不影响理解，通常说明只是材料分类，没有形成真正的论证推进。

## 两类常用长文路径

下面都只是可调用路径，不强制凑齐。

经验、关系、业务和现实摩擦型文章可以参考

`摩擦现场 → 人话翻译 → 来路或机制 → 影响升级 → 边界与反例 → 判断工具 → 行动触发`

认知、思维、学习、读书和研究型文章优先读取 `references/cognitive-writing.md`。常见推进可能是

`真实问题或认知张力 → 旧解释不够用 → 证据进入 → 机制展开 → 替代解释或反例 → 判断收窄 → 最小认知模型 → 迁移`

两条路径都不是模板。真正标准是每一部分都改变了读者的理解，且顺序有逻辑牵引。

系列文章先继承已经确认的概念、结构和语气。新一篇必须带来新的冲突、证据、机制、模型、边界或工具，不能换案例复述上一篇。

## 科学与知识内容

涉及心理、认知、健康、技术、商业或社会科学时，采用当前可核验的理解。

- 分开研究结论、作者解释和用户经验。
- 不把相关性写成因果，不把单篇研究写成定论。
- 不用“科学证明”替代具体研究条件。
- 学术争议会改变建议时，正文给出边界。
- 同时寻找最强替代解释和可能改变结论的反例。
- 知识只在能解释眼前问题、支持判断或帮助迁移时出现。

把术语翻译成人话，但不要牺牲准确性。

## 素材要经过策展

公众号文章尤其容易因为研究充分而材料过量。正文只保留真正承担工作的素材。

故事、案例、研究、数字、原话和比喻进入正文前，先问它负责什么。它可以证明事实、解释机制、制造比较、让抽象关系可以感知、构成反例、限定边界或帮助迁移。删掉以后如果只是少一点热闹，优先删掉。

一个生动案例不能单独证明普遍规律。传播性不能提升证据等级。

## 段落服务于论证

不规定段落句数。一个完整观点尽量在一个相对完整的段落里展开，让判断、解释、条件、例子和限定保持连续。只有逻辑动作、人物、时间、问题或讨论对象发生变化时再换段。

减少连续单句成段、碎片化小标题和短句堆叠。单句段只在确实需要强调、明显转折、关键事实或必要停顿时使用。小标题负责导航，不代替段落之间的逻辑关系。

## 标题最后取

标题从正文最硬的问题、冲突、判断或认知收益里来。它必须兑现。

可优先考虑下面几类。

- 熟悉场景加隐藏代价。
- 一句嘴替判断。
- 一个能改变读者观察方式的问题。
- 一个正文已经证明、但与默认直觉存在张力的判断。

避免虚假数字、夸大承诺、制造普遍敌人和“所有人都被骗了”式标题。反常识只可以是入口，正文最终要给出更准确的解释和边界。

## 结尾完成真正的交付

结尾不强制让读者“做一下”。先看正文最终交付了什么。

经验和实用型文章可以落在一个具体动作，例如记录一次真实摩擦、下次谈话先问一个问题、用一个标准重看当前选择、停止一个无效动作或做一个小实验。

认知型文章也可以落在一个可迁移的判断问题、一个观察信号、一条适用边界、一种新的解释方式，或者一个已经收窄但仍然未知的问题。只有正文自然导向具体行动时，才给行动建议。

不要突然要求点赞、转发、改变人生，也不要为了形式完整重新总结全文或强行升华。
